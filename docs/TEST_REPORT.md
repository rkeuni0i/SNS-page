## 발견하여 수정한 버그: 시드 SQL 한글 깨짐

**증상** — 가입자 리스트 화면에서 이름이 `ê¹€ì‹œë¯¼` 로 깨져 보였습니다. 반면 피드 본문의 한글은 정상이었습니다.

**원인** — 애플리케이션 문제가 아니라 **SQL 파일 로딩 문제**였습니다. DB에 저장된 바이트를 확인하니 이렇게 나왔습니다.

```
저장된 값 : C3AA C2B9 E282AC ...   ← UTF-8을 latin1로 오해석한 뒤 다시 UTF-8로 인코딩 (이중 인코딩)
정상 값   : EAB980 EC8B9C EBAFBC   ← '김시민'
```

`mysql < data.sql` 로 실행할 때 **클라이언트 문자셋이 utf8mb4가 아니면** UTF-8로 저장된 파일의 한글이 깨진 채로 들어갑니다. 피드 본문이 멀쩡했던 이유는 그 데이터는 SQL 파일이 아니라 웹 앱의 JDBC 커넥션(UTF-8)을 통해 들어갔기 때문입니다.

**수정** — `schema.sql`과 `data.sql` 첫머리에 `SET NAMES utf8mb4;` 를 추가하고, `SeedDataGenerator`도 이 줄을 함께 출력하도록 고쳤습니다. 이제 클라이언트 기본 설정과 무관하게 파일 스스로 문자셋을 선언합니다.

**검증** — 일부러 `--default-character-set` 옵션 **없이**(= 깨지던 조건 그대로) 다시 로드했더니 바이트가 정확히 일치했습니다.

이 버그는 정적 분석으로는 절대 잡히지 않고, 실제로 띄워서 화면을 봐야만 드러나는 종류였습니다. 그리고 가은님 PC에서도 똑같이 재현됐을 문제입니다.

## 항목별 상세

### 1. 인증 · 세션

- 올바른 계정 로그인 → `main.jsp` 리다이렉트
- 잘못된 비밀번호 / 없는 아이디 → 각각 알맞은 안내 문구
- **세션 고정 공격 방어 확인**: 로그인 전후 세션 ID가 실제로 바뀜
  `726F992E...` → `53BC3E66...`
- 비로그인 상태로 `main.jsp` `userList.jsp` `feedAdd.jsp` `withdraw.jsp` 접근 → 전부 `login.html` 로 차단
- 로그아웃 후 재접근 → 차단 확인

### 2. 저장형 XSS 방어

`<script>alert('해킹')</script>` 을 본문으로 등록한 뒤 **실제 Chromium으로 페이지를 열었습니다.**

- 다이얼로그가 뜨지 않음 (스크립트 미실행)
- 화면에는 문자 그대로 표시됨
- 속성 이탈 시도 `" onerror="alert(1)` 도 `&quot; onerror=&quot;` 로 무력화
- DB에는 원문 그대로 저장 → 출력 시점에만 이스케이프하는 올바른 방식

### 3. 권한 (구버전 최대 취약점)

- 폼에 `id=lee@abc.com` 을 위조해 글을 올려도 작성자는 **세션 사용자**로 저장됨
- 비로그인 상태의 탈퇴 요청은 차단, 대상 계정 그대로 유지
- 비밀번호가 틀리면 탈퇴 거부, 계정 유지

### 4. 이미지 업로드

- 원본 `photo.png` → `242608d3-adaa-4e1e-aaaf-04455e138ffc.png` (UUID로 저장)
- 저장된 파일이 원본과 바이트 단위로 동일 (무결성)
- 브라우저에서 이미지 정상 로드 및 렌더링
- `.jsp` 업로드 거부 → 웹셸 업로드 차단 확인
- 파일명 `../../../../WEB-INF/web.xml` 거부 → **`web.xml` 손상 없음 확인**
- 6MB 파일 거부 (5MB 상한)

### 5. 데이터 정합성

- 회원 탈퇴 시 본인 피드 3건 CASCADE 삭제, 타인 피드는 보존
- 존재하지 않는 회원으로 피드 삽입 시 DB가 거부
  `ERROR 1452: a foreign key constraint fails (fk_feed_user)`
- 이모지 `🎉` 저장 및 출력 성공 (기존 `utf8` 스키마라면 실패했을 케이스)
- 여러 줄 입력의 줄바꿈 유지

### 6. 입력 검증

- 빈 본문, 4096자 초과 본문 거부
- 비밀번호 확인 불일치 거부 (**기존에는 `ps2`를 검사조차 하지 않았음**)
- 8자 미만 비밀번호, 이메일 형식 아닌 아이디 거부
- 중복 가입 거부
- 저장된 해시 길이 44자, 평문과 불일치 확인

### 7. 전역 예외 처리

DB 프로세스를 강제 종료한 뒤 페이지에 접근했습니다.

- 사용자 화면: `일시적인 서버 오류로 요청을 처리하지 못했습니다. 잠시 후 다시 시도해 주세요.`
- 스택 트레이스 · SQL · 내부 클래스명 노출 없음
- 서버 로그에는 `SEVERE: [mysns] Unhandled exception at /mysns/error.jsp` 로 상세 기록
- DB 복구 후 커넥션 풀이 자동 재연결되어 정상화

### 8. 인덱스 효과 (피드 20,005건 기준)

```
[개선 후]  ORDER BY ts DESC LIMIT 50
  type: index   key: idx_feed_ts   rows: 50      Extra: (없음)

[개선 전 상황]  인덱스 무시
  type: ALL     key: NULL          rows: 20188   Extra: Using filesort
```

| 지표 | 개선 전 | 개선 후 | 차이 |
|---|---|---|---|
| 쿼리 시간 | 38.0 ms | 0.38 ms | **100배** |
| 조회 행 수 | 20,188 | 50 | **404배** |
| 전송 데이터 | 282.3 KB | 0.6 KB | **470배** |

피드 2만 건 상태에서도 `main.jsp` 응답은 **6~10ms**를 유지했습니다.
회원별 피드 조회는 복합 인덱스 `idx_feed_id_ts` 를 사용하는 것도 확인했습니다.

## 참고 사항

**MariaDB로 테스트한 점** — 컨테이너에 MySQL 8을 설치할 수 없어 MariaDB 10.11로 대체했습니다. 사용한 SQL 문법(InnoDB, utf8mb4, FK, `LIMIT ? OFFSET ?`)은 두 DB에서 동일하게 동작하는 범위이며, 스키마·인덱스·제약이 모두 의도대로 생성되는 것을 확인했습니다. 다만 MySQL 8 환경에서 한 번 더 스키마를 적용해 보시길 권합니다.

**JDBC 드라이버** — 테스트에서는 MariaDB 드라이버를 썼습니다. 애플리케이션 코드는 JNDI 이름(`jdbc/mysns`)만 참조하고 드라이버 클래스를 직접 쓰지 않으므로, 실제 검증 대상 코드에는 영향이 없습니다. 가은님 환경에서는 `context.xml`의 드라이버 설정을 그대로 쓰시면 되고, Connector/J 8.x라면 `com.mysql.cj.jdbc.Driver`로 바꿔야 합니다.

**favicon 404** — 브라우저 콘솔에 `favicon.ico` 404가 뜹니다. 파비콘 파일이 없어서 나는 정상적인 현상이며 기능에는 영향이 없습니다.

**서버 로그 한글** — 임베디드 Tomcat 로그에서 예외 메시지의 한글이 `?`로 보였습니다. 로그 핸들러 인코딩 문제로, 정식 Tomcat의 `conf/logging.properties`에 `java.util.logging.ConsoleHandler.encoding = UTF-8` 이 설정돼 있으면 정상 출력됩니다. 애플리케이션 코드와는 무관합니다.

**아직 검증하지 않은 것** — CSRF 방어는 애초에 구현돼 있지 않아 테스트 대상이 아니었습니다. 동시 접속 부하 테스트와 커넥션 풀 고갈 시나리오도 이번 범위에 포함하지 않았습니다.
